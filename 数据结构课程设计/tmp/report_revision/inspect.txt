P018	报告二级标题	1.1 课程设计题目
P019	报告正文	题目 X：生物信息学大规模 DNA 序列片段高通量错配容错检索引擎。本项目实现的软件名称为“DNA 序列片段错配容错检索引擎”，采用 C++ 与 Qt Widgets 构建可直接运行的桌面图形应用程序。
P020	报告二级标题	1.2 项目定位
P021	报告正文	本项目面向数据结构课程设计，目标是在较小、可观察的数据规模上完整展示“参考基因组预处理—K-mer 索引—种子候选—汉明距离验证—结果可视化”的工作流程。它用于验证手写数据结构和算法设计，不将自身描述为可替代真实生物信息学软件的工业级比对系统。
P022	报告正文	题目要求参考基因组由 A、T、C、G 构成，长度约为 2000～5000 bp；Read 通过前 K 位种子定位候选位置，再以允许错配数 k 为阈值逐位计算汉明距离。项目当前实现将参数边界集中定义在 core/DnaLimits.h，并由 UI 层 ApplicationLimits.h 直接引用，从而避免界面限制与核心限制分离。

P025	报告一级标题	2 项目背景与相关研究
P026	报告二级标题	2.1 NGS 短读段比对背景
P027	报告正文	下一代测序技术会产生大量短 DNA Reads，将这些 Reads 定位到参考基因组是后续变异分析等工作的基础。Li 与 Homer 的综述将短读段比对方法按哈希表、后缀结构和排序等索引思路进行归纳，并指出速度、内存占用、敏感性和容错能力之间存在实际权衡[1]。本课程设计缩小数据规模，但保留了“先建立索引，再批量查询”的核心问题结构。
P028	报告二级标题	2.2 K-mer 与 seed-and-extend 思想
P029	报告正文	BLAT 通过预先建立基因组短词索引来快速发现可能同源的区域，然后进入更细致的比对阶段[2]。该思想与本项目的“种子候选加完整 Read 验证”直接相关。需要强调的是，BLAT 论文描述的是基因组中非重叠 K-mer 的索引，而本题明确要求参考基因组滑动窗口步长为 1，因此本项目索引的是全部重叠 K-mer，不能把两者的实现细节等同。
P030	报告正文	Marçais 与 Kingsford 提出的 Jellyfish 说明 K-mer 可以作为哈希表的键，并可围绕大规模 K-mer 处理优化哈希结构[3]。Jellyfish 实际采用锁无关哈希表和二次探测开放寻址；本项目则依据课程要求手工实现拉链法，并为每个 K-mer 保存位置单链表。因此该文献只用于支撑“K-mer 与哈希表结合”的合理性，而不用于声称两者物理结构相同。
P031	报告二级标题	2.3 代表性短读段比对方法
P032	报告正文	Bowtie 使用 Burrows-Wheeler/FM 索引和质量感知回溯算法在大型基因组上完成允许错配的短序列比对[4]。与 Bowtie 相比，本项目没有压缩全文索引、质量分数、反向互补链搜索或插入删除处理，而是选择更适合课程展示的 K-mer 拉链哈希表和汉明距离。这种取舍使桶数组、冲突链、位置链表和提前剪枝过程可以被清楚解释和测试。

P037	报告二级标题	3.2 输入与输出
P038	报告正文	Reference 支持单行或多行纯文本以及 FASTA；Reads 支持每行一条的纯文本或 FASTA。SequenceFileIO 使用 UTF-8 文本流读取，去除 UTF-8 BOM、空格、制表符和回车，并统一转换为大写。Reference 必须形成一条非空 DNA 序列；Reads 文件中的每条记录都必须非空且只能包含 A、T、C、G。
P039	报告正文	CSV 表头为 Read ID、Sequence、Rank、Position、Hamming Distance、Mismatch Details、Status、Candidates 和 Elapsed us。一个 Read 存在多个合法位置时逐行输出，不只保留最佳位置；没有成功匹配时输出“未命中”记录。文本字段通过双引号包围并将内部双引号转义。
P040	报告二级标题	3.3 状态与异常需求
P041	报告正文	当前交互流程要求用户显式建立索引。若未建立索引，或 Reference、K 变化使索引失效，检索入口返回明确错误；只改变允许错配数时保留索引但清空旧结果。导入新 Reference 会清除旧 Reads、索引和结果；导入新 Reads 保留有效索引但清除结果。程序关闭时 MainWindow 析构函数清空输入、Reference、会话并释放 SearchEngine，因此重新启动不会恢复上一次运行状态。
P042	报告一级标题	4 总体设计思想
P043	报告二级标题	4.1 分层组织
P044	报告正文	系统分为核心算法层和 Qt GUI 层。core 目录只依赖 C++ 标准基础设施，负责Genome、PositionList、ZipperHashTable、ReadGenerator、SearchResult 和 SearchEngine；ui 目录负责文件对话框、状态模型、表格、绘制、日志和用户反馈。MainWindow 通过 SearchEngine 的公开接口建立索引和检索，UI 不直接访问哈希桶、HashEntry 或 PositionList。

P049	报告一级标题	5 系统逻辑结构与物理结构
P050	报告二级标题	5.1 逻辑结构
P051	报告正文	逻辑上，Reference 是一条线性 DNA 序列；每个长度为 K 的滑动窗口形成一个 K-mer 键；相同键对应其全部出现位置的线性链表；不同键通过哈希函数映射到桶，映射到同一桶的不同键再构成冲突链。查询时，Read 的前 K 位形成种子，种子对应的位置链表就是候选集合。
P052	报告二级标题	5.2 物理结构
P053	报告正文	Genome 以 new char[length+1] 申请连续存储，末尾写入 '\0'。哈希表以 new HashEntry*[capacity] 申请连续桶数组，每个桶保存 HashEntry 指针。HashEntry 内含深拷贝的 Genome 键、位置链表头指针和下一冲突节点指针。位置链表节点 ListNode<int> 分散申请，通过 _next 串联；新位置采用头插法。
P054	报告二级标题	5.3 对象关系与所有权
P055	报告正文	SearchEngine 拥有 Reference、ZipperHashTable、当前 K、错配阈值和最近一次 SearchResult。ZipperHashTable 析构时逐桶删除 HashEntry，HashEntry 析构时逐节点释放位置链表，最后释放桶数组。SearchResult 和 SearchMatch 对匹配数组与错配偏移数组执行深拷贝。该所有权设计避免结果对象引用已经释放的临时 Read 缓冲区。
P056	报告一级标题	6 核心数据结构设计
P057	报告表题	表 3  核心类与手写存储
P059	报告二级标题	6.1 Genome 连续字符数组
P060	报告正文	Genome 的默认对象也分配 1 字节并写入 '\0'，因此 Bases() 始终返回可用的 C 风格字符串缓冲区。构造函数按给定长度复制字符；复制构造与赋值运算符重新申请缓冲区，赋值时先准备新数组再释放旧数组。它没有使用 std::string，满足题目对核心 Reference 连续存储和深拷贝的要求。
P061	报告二级标题	6.2 位置单链表
P062	报告正文	PositionList 是 ListNode<int>* 的别名。InsertPosition 创建节点，将 _next 指向原链表头，再更新头指针。头插法为 O(1)，适合索引构建期间持续追加位置。其副作用是同一 K-mer 的位置链表按构建顺序逆序保存，但检索结果进入 SearchSessionModel 后会按汉明距离和起点排序，因此对外最佳位置规则仍然确定。
P063	报告二级标题	6.3 拉链法哈希表
P064	报告正文	ZipperHashTable 默认由 SearchEngine 使用容量 8191 的桶数组。Hash 函数将 A/C/G/T 映射为 1/2/3/4，以 131 为乘数迭代取模。Insert 先在目标桶的冲突链中查找相同键；若不存在，则创建 HashEntry 并头插到桶链；随后将位置头插到该键的位置链表。_keyCount、_positionCount、_collisionCount 和负载因子用于界面指标展示。
P065	报告二级标题	6.4 结果动态数组
P066	报告正文	SearchResult 未使用 std::vector，而是以 SearchMatch* 管理动态数组。容量从 0 增长到 4，此后按 2 倍扩容；扩容时逐项深拷贝。SearchMatch 按实际错配数保存偏移数组，使汉明距离为 2 的结果只记录两个离散错配位置，避免出现错配后后续字符整体被标错的现象。
P067	报告二级标题	6.5 核心手写结构与 Qt 容器的边界
P068	报告正文	全局搜索显示 core 目录没有 std::string、std::vector、std::list、std::map、std::unordered_map、QHash、QMap、QVector 或 QList。Qt 的 QVector、QList 和 QString 仅出现在 ui 目录，用于读取文件、视图模型、表格数据、轨道布局和绘制线段。这些容器不承担 K-mer 索引、桶冲突链或位置链表功能，因此没有替代课程要求的手写核心数据结构。
P069	报告一级标题	7 核心算法设计与复杂度分析
P070	报告二级标题	7.1 K-mer 索引构建
P071	报告正文	IndexConstruct 令最后起点为 N-K，从 position=0 到 position=N-K 逐位滑动。每次以 Reference.Bases()+position 构造长度为 K 的 Genome 键，并调用 ZipperHashTable::Insert。因而处理位置总数严格为 N-K+1，首位置为 0，末位置为 N-K，步长恒为 1。以 3000 bp、K=6 为例，索引位置数应为 2995；该边界关系已包含在自动测试中。
P072	报告二级标题	7.2 种子候选与汉明距离验证
P073	报告正文	Search 首先校验 Read 长度、字符集合以及 K≤Read≤Reference，再截取前 K 位作为 seed。Find 返回 seed 的位置链表。对每个候选起点，算法先排除越过 Reference 末端的区间，再从偏移 0 开始比较等长字符。遇到不同字符时记录偏移并增加 mismatchCount；一旦 mismatchCount>k，立即停止当前候选。只有最终错配数不超过阈值的候选才追加到 SearchResult。
P074	报告正文	本题采用汉明距离，未实现插入和删除，因此不存在字符整体偏移。每个错配偏移都是独立的同列差异；UI 根据这些偏移绘制黄色或红色单元格，并只在匹配位置绘制连接线。
P075	报告二级标题	7.3 随机 Reference 与 Reads 生成
P076	报告正文	GenerateReference 使用 mt19937 和均匀分布从 A/C/G/T 中生成指定长度序列。Generate 为每条 Read 随机选择合法来源起点，复制连续 readLength 个字符，然后在 [K, readLength-1] 区间产生 1～2 个不重复突变偏移，并保证替换碱基不同于原字符。前 K 位种子不被破坏。当 Read 长度恰好等于 K 时没有可突变区域，实现按设计生成 0 处突变。
P077	报告二级标题	7.4 稳定轨道分配
P078	报告正文	GenomeAlignmentWidget 在检索完成后统一收集全部匹配区间，按起点、Read ID、matchIndex 和 readIndex 排序，再将每个区间放入不发生重叠的最低可用轨道。轨道编号存入 m_readLayout；水平滚动和缩放只改变坐标映射，不重新分配轨道。只有重新检索、生成/导入数据、参数导致结果失效或清空结果时才重建布局。
P079	报告二级标题	7.5 时间与空间复杂度
P080	报告表题	表 4  主要算法复杂度
P082	报告正文	提前剪枝不会改变最坏复杂度，但当错误候选较早超过阈值时可以减少实际比较字符数。K 较小时种子重复概率增加，候选 C 通常增大；K 较大时候选减少，但若 Read 前 K 位存在真实突变，单前缀种子方案会漏掉正确位置。这也是随机生成器保护前 K 位的原因。

P085	报告一级标题	8 系统界面与交互设计
P086	报告二级标题	8.1 整体布局
P087	报告正文	主窗口采用深色 Fusion 风格，初始尺寸 1640×980，最小尺寸 1280×760。顶部保留导入 Reference、导入 Reads 和导出结果；左侧集中参数设置、生成 Reference、生成 Reads、建立索引、批量检索、当前 Read 检索和清空结果；中间为全局概览、局部沙盘和精确详情；右侧为 Reads/检索结果双页签以及当前 Read 的全部匹配位置；底部为可上下调整 72～140 像素的运行日志区域。
P088	报告二级标题	8.2 全局概览、局部沙盘与精确详情
P089	报告正文	全局概览用颜色区分 0、1、2 处错配的成功区间，并显示当前视口。局部沙盘按碱基单元格绘制 Reference 和 Reads，支持拖动、滚动、Ctrl+滚轮缩放、适应全局和重置视图。Read 整体以成功底色和边框表达命中，只有实际错配单元格使用黄色或红色。精确详情只保留 Reference、Read 和“比对关系”三行，错配单元格显示碱基变化及绝对位置，三行共享横向滚动。
P090	报告二级标题	8.3 选择同步与连接关系
P091	报告正文	用户可从局部沙盘、Reads 列表或检索结果表选择 Read，SearchSessionModel以稳定 Read ID 同步三处状态。默认检索完成后沙盘不自动选中 Read；只有显式选择某一成功位置时才绘制该 Read 与 Reference 的逐碱基细线。错配位置不绘线；连接线按被其他 Read 占据的纵向范围切成多个线段并绕经空隙，且绘制层级低于字符和错配高亮。点击沙盘空白区域会清除选择和全部连接线。
P092	报告二级标题	8.4 Reads 与结果面板
P093	报告正文	Reads 列表展示 Read ID、序列预览、长度和突变数，并在下方显示完整序列、来源位置和突变变化。单击一行会填入左侧单条检索框并更新当前候选表；双击只触发一次单条检索。批量完成后自动切换到检索结果页；结果按最佳位置、距离和状态展示，当前 Read 的匹配位置区域始终随选择更新。
P094	报告二级标题	8.5 日志、进度与即时反馈
P095	报告正文	运行日志最多保留 200 个文本块，明确记录索引构建和检索的开始、完成、参数、候选数、匹配数及微秒耗时。Snackbar 从窗口左下方向右进入，可同时堆叠最多 5 条；成功消息约 1.5 秒、错误消息约 2 秒后向上淡出。相同消息在短时间内重复出现时复用现有 Snackbar 并重启计时，以降低动画堆积开销。

P103	报告一级标题	10 系统运行结果及正确性分析
P104	报告二级标题	10.1 记录结果的数据来源
P105	报告正文	项目保留 test_reference.fasta、test_reads.txt 和 DNA_Search_Results.csv。test_reference.fasta 是 3000 bp、仅含 A/C/G/T 的固定 Reference；test_reads.txt 是单独的 50 条、每条 30 bp 的导入测试夹具。现有 CSV 中也记录了 50 条长度为 30 bp 的 Read，但其序列与 test_reads.txt 不同，因此正文不把二者描述为同一次运行。经重新核对，CSV 的每条序列在该 3000 bp Reference 的记录位置上均满足所写汉明距离。
P106	报告二级标题	10.2 默认参数 CSV 结果
P107	报告表题	表 6  现有 CSV 记录的实际统计结果
P109	报告正文	对 CSV 的二次核对包括：按每条 Read 前 6 位重新扫描 Reference，得到的种子出现次数与 Candidates 列一致；按记录起点逐字符重新计算汉明距离，与 Hamming Distance 一致；所有差异均位于前 6 位之后。由此可以确认该记录同时体现了种子候选、1～2 处替换错配和完整 Read 验证。
P110	报告二级标题	10.3 结果确定性与显示一致性
P111	报告正文	SearchEngine 返回种子链表中的全部合法位置；SearchSessionModel 再按汉明距离升序、起点升序排列，因此距离相同时最小起点稳定成为最佳位置。MismatchViewData 同时保存 Read 内偏移、Reference 绝对位置、参考碱基和 Read 碱基，右侧表格、沙盘和精确详情使用同一结果对象，避免各视图独立重新计算造成不一致。
P112	报告二级标题	10.4 索引耗时与哈希负载对比实验：待补充
P113	报告正文	待补充。界面能够显示建索引耗时、不同 K-mer 数、桶容量、冲突数和哈希负载，但当前保存材料中没有一组可复核的多 K 对照日志，因此不填写具体比较数字。后续应在同一 Reference、同一硬件条件下分别取 K=2、6、10，记录索引指标与候选总数后再作分析。

P129	报告二级标题	12.1 直接运行
P130	报告正文	进入“250021_张三_计算机技术_执行程序”目录，双击 DNA_SearchEngine.exe。必须保留 EXE、Qt DLL、MinGW DLL、platforms、imageformats、styles 等插件目录的相对位置，不能只复制 EXE。程序不依赖 Qt Creator，正常发布包无需重新编译。
P131	报告二级标题	12.2 推荐操作步骤
P132	报告正文	第一步，点击“生成参考基因组”或导入合法 Reference。第二步，点击“随机生成 Reads”或导入 Reads。第三步，设置 K 和允许错配数并点击“建立索引”。第四步，在 Reads 列表中选择一条 Read 执行单条检索，或点击“高通量批量检索”。第五步，在全局概览、局部沙盘、检索结果和候选位置表中选择结果。第六步，按需点击“导出结果”保存 CSV。
P133	报告正文	若改变 K，必须重新点击“建立索引”；改变允许错配数只需重新检索。相同 Reference 允许重复建立索引，每次都会刷新构建时间和哈希指标。清空检索结果不会删除 Reference、Reads 或有效索引。
P134	报告二级标题	12.3 输入文件格式
P135	报告正文	Reference 文件可以是 FASTA，也可以是只含 A/T/C/G 的纯文本，多行会拼接为一条序列。Reads 文件可以是 FASTA，或每行一条 Read 的纯文本。随发布材料提供 test_reference.fasta 和 test_reads.txt，用于验证导入、建索引、单条检索和批量检索；使用它们时推荐保持 K=6、k=2、Read 长度 30。

P141	报告二级标题	13.2 客观限制与可验证改进方向
P142	报告正文	当前只使用 Read 前 K 位作为唯一种子，因此正确位置的前 K 位发生突变时可能没有候选。可以在不改变核心课程要求的前提下研究多种子或分段种子，但需重新分析候选去重与时间空间代价。当前随机生成器通过保护前 K 位确保测试 Read 可被该算法召回，这是一项明确的实验前提。
P143	报告正文	当前比对只计算等长字符的汉明距离，不能处理插入、删除、反向互补链和碱基质量分。Bowtie 等成熟工具采用更复杂的压缩索引和回溯策略，本项目不应夸大到真实 NGS 工作负载。若扩展功能，应先保持现有手写结构的可测试性，再分别引入反向互补查询、多个种子和可选的带状动态规划。[4]
P144	报告正文	GUI 当前在主线程中执行批量检索，并通过进度条和事件处理维持反馈。课程数据规模下已通过测试；若扩大 Reference 或 Reads 数量，应将不可变索引与后台任务结合，同时设计取消、进度和结果提交边界，避免 UI 模型与核心对象跨线程悬空。
P145	报告一级标题	14 总结
P146	报告正文	本课程设计围绕题目 X 完成了可运行的 C++/Qt 桌面程序。核心层手工实现连续 Genome 字符数组、动态桶数组、HashEntry 拉链节点和 K-mer 位置单链表；索引按步长 1 覆盖 N-K+1 个位置；检索以 Read 前 K 位产生候选，再通过汉明距离和超阈值提前剪枝验证。
